# 灵墨（Lingmo）— 开发路线图

分五个阶段递进，每阶段独立可验收。**当前只实现阶段一**，后续阶段待前序验收通过后再启动。建议把每一阶段当作一个独立的可运行里程碑，而非一次性铺开。

## 阶段总览

| 阶段 | 主题 | 核心交付 | 依赖 |
|------|------|----------|------|
| 阶段零 | 项目脚手架 | 前后端可跑通的空架子 | 无 |
| 阶段一 | Story Bible 地基 | 设定库 + 数据模型 + 设定管理界面 | 阶段零 |
| 阶段二 | 人工主导闭环 | 单章写作 + 自动沉淀 + 一致性提示 + 导出 | 阶段一 |
| 阶段三 | 自动驾驶 | 大纲驱动多章推进 + 暂停/注入 | 阶段二 |
| 阶段四 | 对话式构思 | 自然语言构思 → 结构化约束 | 阶段三 |

---

## 阶段零：项目脚手架

**目标**：前后端能本地跑通，LLM 与嵌入能连通。

**任务**

1. 初始化 `backend`（FastAPI + venv + 依赖）与 `frontend`（Vue 3 + Vite + TS + Naive UI）。
2. 搭好 `domain / application / infrastructure / interfaces` 四层空骨架与依赖注入。
3. 配置 `.env` 与 LLM Provider（OpenAI 兼容，接入 DeepSeek 测通一次调用）。
4. 接入本地嵌入 `bge-small-zh-v1.5` 并验证能产出向量。
5. 初始化 SQLite 与 ChromaDB 连接。

**验收标准**

- `uvicorn` 启动后 `GET /api/v1/health` 返回 200。
- 前端 `npm run dev` 能打开并调用后端健康检查。
- 能成功发起一次 LLM 补全（返回中文文本）。
- 能对一段中文文本成功生成嵌入向量并存入/读回 ChromaDB。

## 阶段一：Story Bible 地基（当前目标）

**目标**：把六类设定实体（世界观/人物/地点/时间线/伏笔/关系）做成可增删改查、可关联、可视化的设定库。

**任务**

1. 按 [03-数据模型.md](03-数据模型.md) 建全部表与迁移脚本。
2. 实现 `domain` 层实体与 `infrastructure/persistence` 仓储。
3. 实现 `interfaces/api/v1` 下六类实体的 CRUD 路由 + 关系创建/删除。
4. 前端实现「设定面板」：左侧实体列表、右侧详情编辑、表单校验。
5. 前端实现「知识图谱」视图：ECharts 节点-连线展示实体关系，点击节点直达编辑。
6. 编写单元测试覆盖仓储与路由。

**验收标准**

- 能创建作品，并在其下新增/修改/删除六类实体，刷新后数据仍在。
- 能在任意两实体间建立/删除关系，图谱视图正确渲染连线。
- 人物、世界观等实体字段完整（对齐数据模型表），非法输入有校验提示。
- 单元测试通过，覆盖 CRUD 与关系操作。

## 阶段二：人工主导闭环

**目标**：实现「一章章写/改，系统自动沉淀设定并提示冲突」的完整主链路。

**任务**

1. 实现 `application/write_chapter`、`continue_chapter`、`rewrite_passage` 用例。
2. 实现 `build_context` 上下文装配（Story Bible 相关实体 + 章级摘要链 + 章前指令）。
3. 实现 `settle_chapter`：定稿后抽取本章新增设定，生成「设定变更建议」供作者确认。
4. 实现 `consistency_check` 规则库版（人物已知信息、时间线先后、伏笔状态）。
5. 实现章前指令强约束注入。
6. 实现 Markdown/TXT 导出。
7. 前端实现写作编辑区（含流式生成、改写、章前指令框、一致性高亮提示）。

**验收标准**

- 能开新章/续写/改写，生成内容为中文且能流式显示。
- 章前指令会被明显遵守（如「让 A 与 B 决裂」后生成内容出现对应情节）。
- 定稿一章后，系统能提出本章新增的人物/事件/伏笔建议，作者确认后落库。
- 生成内容违反已有人设/时间线时，能高亮提示冲突。
- 能导出整本 Markdown。

---

## 阶段三：自动驾驶

**目标**：在作者定好的大纲约束下，引擎自主推进多章，可随时暂停与注入构思。

**任务**

1. 实现大纲管理（卷/幕/章三级，拖拽排序）。
2. 实现 `auto_pilot` 用例：逐章装配→生成→检查→落库→下一章，含熔断与进度 SSE 推送。
3. 实现暂停/恢复，以及「注入构思后重新规划后续大纲」。
4. 实现张力评分与文风相似度检测（漂移告警）。
5. 前端实现自动驾驶控制面板（开始/暂停/进度/注入入口）。

**验收标准**

- 给定大纲，能连续生成 ≥3 章，各章人设/伏笔基本一致。
- 连续失败超阈值能自动暂停并给出诊断信息。
- 暂停后注入一条构思，引擎能据此调整后续章节内容。
- 每章生成后展示张力评分，历史曲线可查看。

---

## 阶段四：对话式构思注入

**目标**：把自然语言构思自动翻译成结构化约束，形成「边聊边改」闭环。

**任务**

1. 实现 `inject_idea` 的 `chat` 通道：LLM 意图识别，抽取目标人物/事件/因果。
2. 产出「设定变更建议」并支持作者确认/编辑后应用。
3. 应用后触发大纲重规划与一致性检查。
4. 前端实现聊天面板，与设定面板、大纲联动。
5. 三种写作模式（人工主导/自动驾驶/对话共创）在统一工作台内可切换。

**验收标准**

- 在聊天框输入「让 X 黑化，因为他知道了身世」，系统能正确识别目标人物与因果，生成可确认的设定变更建议。
- 确认后，X 的人物档案与相关大纲被更新，后续生成体现该变化。
- 三种模式切换时 Story Bible 状态不丢失。

---

## 里程碑约定

- 每阶段结束做一次「验收」，验收标准全过才算完成，再进入下一阶段。
- 阶段一完成后，才允许接触 LLM 写作相关代码；阶段一的设定库是后续一切的基础，优先把它做扎实。
- 每个阶段的功能都按 PRD 的「触发 → 处理 → 结果」口径实现，避免只做 UI 空壳。
