# 灵墨（Lingmo）— AI 网文协作写作工作台

> 个人自用、本地优先的中文网络小说 AI 协作写作工作台。核心是「人机共创」：作者主导构思与方向，AI 负责执行、记忆与一致性维护。

## 一句话定位

在「自动驾驶批量写」与「聊天式共创」之间取中：让 AI 帮你把世界观、人物、伏笔这些设定**结构化地沉淀**下来，同时允许你**随时把构思插进去**，而不是让 AI 一跑到底、你插不上手。

## 为什么做这个

现有开源项目大致分两派，各有短板：

- **纯自动驾驶派**（PlotPilot、harnessNovel、AI_NovelGenerator）：长篇一致性、设定管理强，但作者干预难、易跑偏、AI 味重。
- **纯对话共创派**（SillyTavern、ReNovel-AI、zenstory）：人主导、交互自然，但长文一致性弱、设定容易散。

本项目的差异化：**自动驾驶 + 构思注入**。既保留自动驾驶的生产力，又把「作者的一句话构思 → 引擎的结构化约束」这条转换链路做成核心能力。

## 核心概念

| 概念 | 含义 |
|------|------|
| Story Bible（设定圣经） | 世界观、人物、地点、时间线、伏笔等全部设定的统称，是系统最底层的状态 |
| 构思注入 | 作者把想法/构思输入系统的动作，分三种粒度（见 PRD） |
| 章前指令 | 每章生成前，作者写的一段「这章要什么走向/情绪/桥段」的强约束 |
| 自动驾驶 | 引擎在作者定好的大纲与设定约束下，自主推进多章生成 |
| 一致性检查 | 生成内容与 Story Bible 的冲突检测，防止人设崩坏、伏笔丢失 |

## 三种写作模式

1. **人工主导**：一章一章写，你写/改，并在需要时点击“定稿沉淀”，系统抽取设定建议并提示一致性冲突。
2. **自动驾驶**：你定好大纲和设定，引擎自主推进多章，你随时暂停、注入指令。
3. **对话共创**：在聊天框里用自然语言描述构思，系统自动解析成结构化约束并更新设定库。

三种模式共用同一套 Story Bible 状态，随时切换不丢设定。

空作品进入“写作”即可填写标题、章前指令和正文，点击“保存草稿”直接保存在本地；手写不需要模型密钥。已存章节的标题、正文或章前指令实际变化时，会保留旧版本，并回到草稿，清空旧摘要、评分和该章记忆，需要重新审校与定稿。单独校正摘要不保存编辑区其他未提交的修改。

伏笔关联保存期间，同一条伏笔暂停其他操作；切换作品或页签再回来也会保留等待状态。已确认的消费保存先显示真实状态，目录刷新失败会提示统计待刷新。出现“保存结果待核对，请先刷新”时，先点击伏笔面板的“刷新”读取实际结果，再继续指定章节；完整刷新页面及其他浏览器页签不共享这份等待状态。

编辑已有设定只保存实际修改字段：只改伏笔描述不会把保留表单里的旧消费状态带回数据库。保存等待期间的新输入保留为未保存修改；明确清空字段仍可保存。JSON 对象仅换排版或键顺序不算修改，数组顺序算修改；清空 JSON 输入用于清除对象或列表，字面 null 不作为清空。两处同时改同一字段仍可能以后一次保存覆盖，需要作者核对。

新章保存回应丢失时，点击“核对原保存”会读取原次创建结果，保留等待期间的新编辑，不自动再建一章或覆盖已存正文。当前浏览器、同一访问地址下会保存待核对记录；刷新后点击“恢复待核对稿”，再明确核对。清理浏览器数据、换地址或换浏览器不能找回这份缓存，数据库备份也不包含它；页面提示缓存失败时请先复制稿件。明确另写一章仍可点击“新章”，同名同稿也能合法保存。删除原章后旧核对不会复活它；“移除本地记录”只清理缓存。

定稿建议由作者勾选确认后才写入设定。页面没收到确认回应时，点击重试会核对原提交，已成功项不会重复创建；失败项可修正后单独重试。另一窗口改稿会阻止旧建议写入，当前文本与候选保留，作者可重新读取章节核对。已有同名设定会明确提示，请到设定面板核对；系统不自动合并。

“深度检查”只核对含已知人物、地点或世界观名称且未命中规则的分块，最多调用模型八次。结果显示实际完成、失败、跳过和未查范围；模型失败或返回无效引文会明确提示未完成，已有规则冲突也会保留。检查只读，不自动保存编辑稿；已查范围没有发现明显冲突仍需作者校对。

## 快速开始

### 环境要求

- Python 3.11+、Node.js 18+
- Windows PowerShell；建议 Node.js 22 或 24。测试文件 runner 无需 shell glob；本轮实际验证环境为 Node.js 24。

### 1. 后端

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
# 复制 .env.example 为 .env，填入 OPENAI_API_KEY（默认 DeepSeek）
copy .env.example .env
.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000
```

### 2. 前端

```bash
cd frontend
npm install
npm run dev
# 浏览器打开 http://localhost:5173/
```

前端 dev server 会把 `/api` 代理到 `http://localhost:8000`。

### 3. 嵌入模型（记忆与检索层）

- 默认本地 `bge-small-zh-v1.5`（fastembed，ONNX 轻量、无 PyTorch），首次运行会自动下载到项目内 `backend/fastembed_cache/`（已加入 .gitignore，之后离线可用，无需重复联网）。
- 若网络受限，可切云端嵌入：在 `.env` 配 `EMBEDDING_SERVICE=openai`、`EMBEDDING_BASE_URL`、`EMBEDDING_API_KEY`、`EMBEDDING_MODEL`。
- 嵌入/检索失败会降级为「仅章级摘要链」。定稿面板会明确显示记忆写入或后置质量检查未完成的警告，作者可稍后重试；有来源的章切片会核对当前正文并排除过期片段。

### 4. 测试

```bash
cd backend
.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py' -v
```

推荐从仓库根执行隔离的统一检查，避免测试加载正式配置或触发真实模型/嵌入：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\check.ps1
```

只检查前端，在 `frontend` 执行 `npm.cmd run check`；其顺序是测试、类型检查和构建。单独的 `npm.cmd run build` 也会先执行类型检查。

### 5. 一键启动与服务检查

安装依赖后，可双击仓库根的 `start.bat`。它保留前后端日志窗口，等待后端健康身份、前端页面及 API 代理均通过检查再打开浏览器。端口被其他服务占用或代理错误会报错，不停止占用进程。`start.bat --check` 只验证依赖与运行文件，不启动服务。

服务运行后的只读检查：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\check_services.ps1
```

### 6. 数据备份与恢复

先确认要备份的实际 SQLite 路径：默认是 `backend\data\lingmo.db`，若已自定义 `DATABASE_URL`，应显式改为自己的工作库。工具不读取 `.env`、不猜库名。

```powershell
.\backend\.venv\Scripts\python.exe .\scripts\backup_database.py --source .\backend\data\lingmo.db --output-dir ..\lingmo-backups
```

工具以只读方式打开源库，使用 SQLite online backup，包含已提交的 WAL 数据；创建带 UTC 时间与 UUID 的新文件，验证完整性后才报告成功，不覆盖旧备份。不要用普通文件复制代替运行中的数据库一致性备份。未配置 API Key 时，已有设定、章节和本地导出仍可使用，生成会明确报缺少配置。

恢复时先停止前后端服务和活动写作任务，确认目标工作库的路径与所选备份，并保留原数据库及可能存在的 `-wal`、`-shm` 文件作为同一组回退资料。将这组原文件移到独立保留目录后，把已验证备份复制到原数据库路径，重启再检查作品、章节和版本。不要在服务运行期间覆盖数据库，也不要把旧 WAL/SHM 与恢复的备份混用。当前工具只提供备份，不自动执行恢复或删除原数据。

## 关键假设（可随时推翻）

以下决策由项目经理在缺少你明确输入时自行拍板，如与你预期不符，直接告诉我即可：

1. **产品名**「灵墨」为工作标题，可随时改名。
2. **形态**为本地 Web 应用（浏览器访问 `localhost`），暂不做桌面壳、不做移动端、不做多用户。
3. **模型**默认走 OpenAI 兼容接口，优先 DeepSeek，可切换 Doubao/Qwen/Claude/Gemini；嵌入默认本地 `bge-small-zh-v1.5`。
4. **前端**选 Vue 3，与参考项目 PlotPilot 技术栈一致，方便直接借鉴其领域建模与组件。
5. **部署**以「单机本地跑」为第一优先级，Docker 作为可选加分项，不阻塞主线。
